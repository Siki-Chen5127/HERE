## 11 月 21 日凌晨｜首次部署、安装与恢复

| 发现与影响 | 处理动作 | 结果 |
| --- | --- | --- |
| Expo Web 首次构建找不到 `wa-sqlite.wasm`。 | 将 `wasm` 加入 Metro 的资源扩展名，分别为 Vite 管理端和 Expo 学生端配置项目子路径及同域 API。 | 两个前端均完成生产构建。 |
| 只读盘点一度因从项目根目录运行而找不到远端脚本。传到 Ubuntu 后，Windows CRLF 换行又导致 Bash 报错。 | 用 `$PSScriptRoot` 定位脚本，将 Bash 脚本转换为 LF 后重跑。 | 审计成功。服务器有 2 vCPU、约 1.9 GiB 内存和约 17 GiB 可用磁盘，盘点时负载较低。确认项目子路径和本地端口 `18882` 可用。 |
| SSH 连接反复弹窗。受限进程无法读取私钥，多个 SSH agent 和 AskPass 会话叠加，部分调用还缺少启动变量。 | 终止挂起会话，补齐 AskPass 启动配置，通过受控权限单次解锁，成功后复用同一 agent 并移除重复提示所需的环境变量。核对 SSH 与 SCP 使用同一套客户端。 | 只读检查和首轮上传完成。耗时较长的后续发布中，旧 agent 过期或失联仍造成重试。 |
| 上传前发现后端部署包多了一层 `app` 目录。修好包后，Windows 上的 SCP 又因端口参数写法不同而失败。 | 重建部署包并校验目录结构，将 SCP 端口参数改为大写 `-P`。将生产环境配置放到共享目录，使后续发布可以沿用同一 JWT 密钥。 | 修正后成功上传。 |
| 远端缺少 Python venv 组件。首次安装留下半成品虚拟环境，脚本只检查目录存在，重试时找不到 pip。 | 安装 `python3-venv` 和所需 pip 组件。脚本改为检查虚拟环境中的 Python 和 pip，发现残缺环境即重建。 | 依赖安装继续执行。 |
| 安装过程长时间无输出。Codex 在本地脚本中发现，串行读取 stdout 和 stderr 可能导致管道阻塞。 | 改为并行读取两个输出流，结束卡住的本地等待后重新执行部署。 | 重试推进到后端依赖安装。 |
| `pyodbc` 编译缺少 ODBC 头文件 `sql.h`。 | 把 `unixodbc-dev` 和编译工具加入远端安装步骤，避免已有虚拟环境时跳过检查。 | `pyodbc` 编译和依赖安装成功。 |
| systemd 服务启动后立即退出。Codex 从服务日志定位到 Python 3.14 与 SQLAlchemy 2.0.39 的类型解析不兼容。 | 将远端依赖升级到 SQLAlchemy `2.0.58`，同步更新工作区依赖和部署包。 | `personal-safety-check-in.service` 正常运行，健康接口报告生产环境与 SQLite。 |
| 后端恢复后，Nginx 返回页面 500。静态文件在发布目录中，但 Nginx 无法穿过上级目录。 | 补齐静态文件路径所需的目录遍历权限，将设置同步到部署脚本，检查并重载 Nginx。 | 两个网页和静态资源均返回 `200`，未登录访问受保护 API 返回 `401`。已有站点继续使用原入口。 |
| 管理员登录核验失败。线上已有账号仍使用初始密码，与部署时生成的凭据不一致。 | 更新现有管理员密码并递增 `auth_version`，用部署凭据重新验证登录。 | 线上接口登录成功，返回 `admin` 角色。 |
